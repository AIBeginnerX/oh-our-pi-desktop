01 · What it is소개

Agents are good.
Juggling them is not. 에이전트는 훌륭합니다.
여러 개를 오가는 일이 문제죠.

Each coding agent lives in its own terminal or app, with its own login, history and approval prompts. OOP puts them side by side with one diff, one terminal and one approval flow. 코딩 에이전트마다 터미널이나 앱, 로그인, 기록, 승인 프롬프트가 따로 있습니다. OOP는 이들을 나란히 놓고 diff, 터미널, 승인 흐름을 하나로 맞춥니다.

Not a hosted service. OOP runs on your computer. Projects, provider logins and agent work stay there. There is no OOP account and no OOP server. 호스팅 서비스가 아닙니다. OOP는 내 컴퓨터에서 실행됩니다. 프로젝트, provider 로그인, 에이전트 작업이 모두 그곳에 남고, OOP 계정도 OOP 서버도 없습니다.

Built on T3 Code. OOP is a fork of T3 Code by T3 Tools Inc. (MIT), based on upstream v0.0.44. Almost all of the foundation is their work. T3 Code 기반입니다. OOP는 T3 Tools Inc.의 T3 Code(MIT)를 포크한 프로젝트이며 업스트림 v0.0.44를 기반으로 합니다. 기반 코드의 거의 전부가 T3 Code 팀의 작업물입니다.

03 · OOP Crew

Cheap models for the bulk.
A strong one to check. 대부분은 저렴한 모델로.
검토는 강한 모델로.

Turn on Crew next to the model picker. The chat's own model becomes the brain, and OOP routes the rest by role. 모델 선택기 옆에서 Crew를 켜면, 채팅의 모델이 brain이 되고 나머지는 역할에 따라 나뉩니다.

Brain Plans and talks to you. 계획을 세우고 사용자와 대화합니다.
Worker Routine work: searches, edits, tests. 반복 작업: 검색, 수정, 테스트.
Expert Hard implementation. 어려운 구현.
Auditor Reviews turns that changed files. 파일을 바꾼 턴을 검토합니다.
  1. You ask. The chat's own model is the brain: it plans and talks to you.요청을 보냅니다. 채팅의 모델이 brain이 되어 계획을 세우고 사용자와 대화합니다.
  2. Routine work goes to a worker: searches, edits, tests.반복 작업은 worker가 맡습니다: 검색, 수정, 테스트.
  3. Hard implementation goes to an expert.어려운 구현은 expert가 맡습니다.
  4. A turn that changed files goes to the auditor. A small, test-passing change of 20 lines or fewer gets a short light review instead of a full audit.파일을 바꾼 턴은 auditor에게 갑니다. 테스트를 통과한 20줄 이하의 작은 변경은 전체 감사 대신 짧은 경량 검토를 받습니다.
  5. The review comes back to the brain.검토 결과가 brain에게 돌아갑니다.
  6. The brain answers you.brain이 사용자에게 답합니다.

What does it cost?비용은 얼마인가요?

OOP itself is free and MIT licensed. Every provider uses your own subscription or API credit, and Crew multiplies usage by running several models per chat. The Usage page shows estimates, not your bill. OOP 자체는 무료이며 MIT 라이선스입니다. 모든 provider는 내 구독이나 API 크레딧을 쓰고, Crew는 채팅 하나에서 여러 모델을 돌리므로 사용량이 늘어납니다. 사용량 페이지는 청구액이 아닌 추정치를 보여 줍니다.

Is it safe to let agents run?에이전트를 실행해도 안전한가요?

Agents run with your account's permissions and can edit files and run commands. New threads default to Full access. For untrusted repositories, switch to Supervised (Settings → General → New threads). Treat pairing links as passwords and prefer Tailscale away from home. 에이전트는 내 계정의 권한으로 실행되어 파일을 수정하고 명령을 실행할 수 있습니다. 새 스레드의 기본값은 Full access이므로, 믿을 수 없는 저장소에서는 Supervised로 바꾸세요(설정 → General → New threads). 페어링 링크는 비밀번호처럼 다루고, 집 밖에서는 Tailscale을 권장합니다.

Does OOP collect telemetry?텔레메트리를 수집하나요?

OOP has no servers and the maintainers receive nothing from your app. The anonymous usage reporter inherited from upstream is off by default and needs your own project key to turn on. OOP에는 서버가 없고 개발자는 앱에서 아무것도 받지 않습니다. 업스트림에서 물려받은 익명 사용 통계 보고기는 기본으로 꺼져 있고, 켜려면 직접 발급한 프로젝트 키가 필요합니다.
